Features

Honest capability map. Shipped items match the CLI and README; sketch items are reserved but not implemented.

Shipped v0.1 + post

Multi-git Projects

project add/list/rm/info/git, plain clones, odm sync (fetch), optional pin file apply/status.

Progen stores

Lifecycle + single-root façade under odm progen (reindex, get/body/ls/tree/backlinks, doctor). Top-level odm find (federated FTS) and odm context (in-store neighborhood) are separate.

Actions

odm run lists and executes named shell tasks from bundle files.

Status & doctor

Workspace snapshot; ODM-side health including worktree orphan/dirty warns and pack_missing.

Worktree slots

add/list/rm/prune/prune --all; --wt on project git and run; dirty + orphans on status/info.

Generators (local)

odm generate materializes local templates; --dry-run previews file count without write.

Agent packs (local)

install/link/list/rm; status agent_packs inventory; doctor pack_missing.

Agent prompt (thin)

odm agent prompt — context work-package (same neighborhood as context).

Sketch / deferred not shipped

  • odm agent start — shell-out to an agent runtime (exit 1 today)
  • odm init --interactive — flag reserved, not implemented
  • Generate remote templates, template.toml / prompts / vars
  • Pack marketplace, pack manifest, config-declared packs
  • Worktree config slots, pin↔slot, auto-prune on doctor, branch templates
  • Many reserved progen store verbs (task/issue/plan/watch/…)
  • odm serve / MCP — non-goals for the v1 design package

Non-goals (by design)

  • Not a monorepo build system (does not replace pnpm, Nx, Cargo workspaces inside Projects)
  • Not a git host, forge, or PR bot
  • Not a second knowledge product — Progen is the store engine; ODM orchestrates
  • No submodule-based multi-repo model
  • The ODM product repository is not a consumer Workspace

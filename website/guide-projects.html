Guide

Projects & pins

ODM manages plain git clones declared as Projects (and Progens with url). No submodules.

Managed vs path-only

  • Managed — entry has url: clone / sync (fetch) / pin / optional delete on rm.
  • Path-only — no url: ODM never runs git; you own the tree. Sync and pin ignore it.

Add and sync

odm project add api --path apps/api --url https://github.com/acme/api.git --branch main
odm project add local --path apps/local          # path-only
odm sync                                         # all managed
odm sync api                                     # one name
odm project list
odm project info api
  • sync = ensure present, then git fetch. Never checkout/reset/merge as part of sync.
  • Origin URL mismatch or non-git junk at path → fail (no silent rewrite).
  • --no-clone on add writes config only.

Pin file

When the Workspace is a git repo and managed clones succeed, ODM can maintain .odm/odm.lock.yaml — a lock of resolved SHAs. Layout still lives in config; pins are not layout truth.

odm pin status
odm pin apply              # checkout each pin rev as detached HEAD
odm pin apply api --force  # if dirty policy requires force

Mental split: sync refreshes remotes; pin apply moves HEAD to locked revs. Optional branch on config is clone preference only — pin authority is the recorded commit SHA.

Remove

odm project rm api              # un-declare; tree kept
odm project rm api --delete     # remove tree if clean
odm project rm api --delete --force

project rm does not delete worktrees/<project>/.

Git through ODM

odm project git api -- status
odm project git api --wt feat -- checkout -b wip
odm project git api -- log -1 --oneline

Args after -- are git argv (not a shell string). Exit code = git’s. Pin auto-maintain on Primary HEAD change only (not slots).

Auth

ODM does not store credentials. Use whatever git already uses (SSH agent, credential helper, …).

Orchestrated Development Management

One desk for many repos, memory, and agents

ODM is a poly-repo workspace OS for humans and AI agents: one config, one CLI, and orchestrated Projects + Progens — without git submodules or a second brain product.

Install ODM Quickstart View on GitHub

v0.1.0 spine + post-0.1 worktrees · generate · agent packs

What is ODM?

A single binary and a Workspace config that declare how your desk is laid out: which git checkouts are Projects, which Markdown stores are Progens, and how actions, worktree slots, and agent packs attach to that desk. Humans and agents use the same odm CLI — not a separate “AI product.”

Honest capability map (shipped vs sketch): Features.

Start here

  1. Install Put odm on your PATH (release tarball or build from source), then verify with odm --version.
  2. Quickstart odm init → add a Project → odm sync → odm status / odm doctor.
  3. Operate day-to-day Guides for pins, Progen search, worktree slots, actions, generate, and agent packs.

Why ODM

Many checkouts, one desk

Declare Projects and Progens in config. Plain clones and optional pins — no submodule lifecycle.

Memory is multi-store

Orchestrate several Progens with scope and federation. One vault is not the whole world.

Agents share the desk

Worktree slots and agent packs put agent work in known places — not ad-hoc clones.

One binary UX

Humans and agents use the same odm CLI. No separate progen product or plugin zoo.

Instead of…

  • Git submodules — plain clones + optional pin file; layout lives in Workspace config.
  • One mega-vault — many Progens, ODM-scoped query; no cross-store wikilinks inside a store.
  • Ad-hoc agent clones — declared Projects, worktree slots, and agent packs on one desk.

Get productive in minutes

odm init
odm project add alpha --path projects/alpha --url <git-url>
odm sync
odm status
odm doctor

Then add Progens for docs/memory, Actions for tasks, worktree slots for parallel work, and agent packs for coding agents.

Who it is for

Humans and agents are equal primary users of the same Workspace — not an AI-only tool with a human afterthought.

  • Humans — CLI, Workspace config, sync/pin/status/doctor, actions.
  • Agents — agent packs, worktree slots, and progen context on that same desk.

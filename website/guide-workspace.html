Workspace & config

Everything ODM does is relative to a Workspace: a root directory with .odm/odm.config.yaml.

Create one

odm init              # cwd becomes Workspace; git init by default
odm init ./desk       # target path
odm init --no-git     # skip git init

Headless init writes minimal config. Empty projects / progens maps are valid. Already a Workspace → refuse.

How ODM finds the Workspace

  • --root <path> — that directory must contain .odm/odm.config.yaml. No walk.
  • Without flag — walk up from cwd looking for config; stop at $HOME (or FS root outside home). First match wins.
  • Empty .odm/ without config does not count.

What lives under .odm/

.odm/
  odm.config.yaml     # tracked — layout source of truth
  odm.lock.yaml       # tracked when present — pins
  cache/              # ignored
  log/                # ignored
  progen/<name>/      # ignored — ODM-side indexes
  agent-packs.json    # pack registry (when used)

Never under .odm/: Project checkouts, Progen store content, worktree slot trees, agent pack payloads. Those live at config-declared paths or under worktrees/.

Global flags you will use constantly

  • --root <path> — Workspace root
  • --json — machine-readable stdout (stable shapes for agents)
  • --project <name> — target Project by config name
  • --progen <name> / --progen-group <name> — scope (repeatable)
  • --wt <slot> — worktree slot (needs Project context)

Scope flags take names only, not filesystem paths. Unknown entity name → hard error (exit 1).

Exit codes (summary)

  • 0 success (including find with zero hits)
  • 1 usage / unknown command / bad flags / unknown name
  • 2 Workspace/config error
  • 3 operation failed (git/pin/store and other ODM operation failures)
  • 4 not found (e.g. missing slot, missing pack source)

odm run: once an Action is found and executed, the process exit code is the action’s exit code (passthrough). Pre-exec failures still use ODM codes above.

Edit config safely

Prefer CLI mutators when they exist (project add, progen add, …). You may also edit YAML directly — then run odm doctor and odm status.

Day-two health loop

odm status
odm doctor
odm doctor --fix    # mechanical ODM repairs only — not destructive git rewrites

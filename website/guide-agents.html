Agent packs & prompt

All AI/agent-facing UX lives under odm agent. Packs are portable bundles of skills/prompts/conventions installed into agent-native homes.

Local pack lifecycle (v1)

odm agent pack install ./agent-packs/demo --home ~/.my-agent/skills
odm agent pack link ./agent-packs/demo --home ~/.my-agent/skills
odm agent pack list
odm agent pack list --json
odm agent pack rm demo
  • Source: local directory. Relative paths resolve under Workspace root (must not escape) or absolute paths. Name = directory basename.
  • --home: required agent-native root (may be outside Workspace). Materializes at <home>/<name>/.
  • install — recursive copy; link — symlink to absolute resolved source.
  • --force: replace existing <home>/<name>/ on install or link. Without force, dest exists → exit 3.
  • Registry: .odm/agent-packs.json.
  • No remote/marketplace; no pack manifest required in v1.

Observation

odm status              # Agent packs section; missing suffix when dest gone
odm status --json       # agent_packs: [{ name, source, path, mode, missing }]
odm doctor              # pack_missing:<name> warn (not fixable)

missing = path has no metadata entry. A dangling symlink counts as present (not missing).

Thin agent prompt

odm agent prompt <id>
odm agent prompt notes:<id>
odm agent prompt <id> --progen notes --json

Packages one note’s in-store context to stdout for agents — same rules as odm context. Not a planner, not a graph walk, not a second prompt engine.

Combine with worktrees

Typical agent loop on a desk:

  1. Install packs into the agent home once.
  2. worktree add a slot for the task branch.
  3. Point the agent at worktrees/<project>/<slot>/ (or use --wt for ODM git/run).
  4. Use find / agent prompt for memory context.

odm agent start is still sketch (not implemented). You start the agent runtime yourself today.

# Split membership module under ≤1000 LOC

## Description

The membership module is at ~993 LOC (production + large inline tests): entity add/rm, path-policy error remap, delete-with-restore, gitignore/pin hooks, `project_git` passthrough, and a CLI-oriented path helper. Next feature growth crosses the AGENTS.md ≤1000 target without a structural split. Same spirit as the prior worktree test extract.

## Affected

- odm-core membership and related re-exports
- Callers of membership add/rm and project git (CLI)

**Summary:** Split the membership grab-bag so every resulting `.rs` file is ≤1000 LOC (prefer production modules lean); no product behavior change.

- One module owns: project/progen membership add and rm (including path escape validation before save, unique path-safe names), delete-with-restore, gitignore/pin side effects, `project_git` with worktree/pin-maintain branching, and a path buffer → rel helper used for CLI, plus a large ScriptedRunner-style unit test bulk.

- Public API used by CLI remains available from the core library façade (re-exports OK) with the same signatures and semantics.
- Prefer extracting shared git test doubles once if multiple modules already paste ScriptedRunner — only as needed to keep files under target; do not build a speculative test framework.
- No CHANGELOG product entry required (pure refactor); module comments OK.

**Key interfaces:**

- Existing membership add/rm and project git functions and error codes (usage vs not_found vs operation) — unchanged
- Path token / resolve_under_root policy — do not weaken; typed path errors may land in [[issues-153-typed-path-resolve-errors]] separately (string remap may remain until then)

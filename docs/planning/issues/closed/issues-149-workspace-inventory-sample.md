# Workspace inventory sample for worktrees and packs

## Description

Primary entity observation is shared (`observe_workspace`), but worktree slots/orphans/dirty and agent packs are re-sampled in status, doctor (orphan pass + dirty pass), CLI project info, and pack list/status/doctor missing probes. Pack “missing” (lexists via symlink metadata; dangling symlink not missing) is implemented three times. Prune pays full dirty probes only to collect registered names.

Extend the sample plane so reporters project; do not add a fourth copy of the glue.

## Affected

- odm-core observation / status / doctor / doctor_worktree / doctor_pack / worktree / agent_pack
- odm CLI project info DTO path (must stop re-implementing sampling)
- Unit and integration tests that script dual worktree_list queues for doctor

## Impact

Shotgun surgery on every new workspace fact; wasted git status probes; drift risk on pack missing and soft-fail policy.

## Proposed Fix

See Agent Brief.

## Blocked by

None

## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement  
**Summary:** One injectable inventory/sample API for per-project worktree facts and workspace agent packs; status, doctor, project info, and prune name collection consume it; pack missing is one method/type.

**Current behavior:**

- `observe_workspace` samples Primary Project/Progen rows once; `status_from_observation` leaves worktree/pack fields empty/None; `build_status` then calls `worktree_list` per project and `pack_list`, computing pack `missing` inline.
- Doctor runs separate orphan and dirty helpers, each calling `worktree_list` (list + per-slot clean probes) again.
- CLI project info reattaches worktree slots/orphans with the same list+orphan glue.
- Pack missing rule appears in status mapping, doctor pack checks, and CLI pack entry DTO conversion.
- Prune obtains registered names via full `worktree_list` (including dirty probes it discards).
- Prune outcome types reuse slot info with `dirty: None` even though JSON prune rows are name+path only.

**Desired behavior:**

- A small inventory API (name flexible) accepts workspace + injectable git and returns, per configured project that is git-backed enough to list worktrees: registered slots (with dirty ternary as today), orphan infos (same orphan definition as today), and a names-only or cheap registered-name set usable by prune without dirty probes when dirty is unused.
- Pack observation returns registry entries plus a single `is_missing` / `missing` fact using the existing lexists rule (path or symlink present; dangling symlink not missing).
- `build_status` / status snapshot fields for worktree_slots, worktree_orphans, agent_packs project from inventory (soft-fail → empty arrays as today).
- Doctor worktree orphan and dirty warns project from **one** sample per project (no double list). Doctor pack_missing uses the shared missing rule.
- Project info worktree fields call the same core inventory helper — no parallel sampling glue in the bin.
- Prune registered-set path does not run per-slot dirty probes.
- Prefer a prune row type that is name+path only (no fake dirty field) while keeping list/status/info slot types with dirty unchanged.
- Public JSON field names, doctor check ids (`worktree_orphan:…`, `worktree_dirty:…`, `pack_missing:…`), severities, fixable flags, and exit codes remain compatible with locked contracts.

**Key interfaces:**

- Existing `worktree_list` / orphan helpers / `pack_list` / `PackEntry` — inventory may wrap or replace internal call sites; external CLI JSON stays stable
- `PackEntry` (or adjacent obs type) owns missing: one `is_missing()` (or equivalent) used by status, doctor, CLI DTO
- Injectable `&Git<R: CommandRunner>` — same style as observation
- Soft-fail policy: sample errors become empty observation for that surface, matching current status/info behavior

**Acceptance criteria:**

- [x] Status, doctor worktree checks, and project info do not each maintain independent worktree list+orphan attach loops
- [x] Doctor orphan + dirty checks together perform at most one `worktree_list` (or equivalent full sample) per project per doctor run
- [x] Pack missing is computed in exactly one shared place; status, doctor, and pack list/DTO use it
- [x] Prune (single-project and `--all`) does not dirty-probe slots solely to learn registered names
- [x] Prune core/JSON row shape has no meaningful dirty field (name+path only)
- [x] Existing CLI/core-desk/doctor tests for status slots/orphans, pack missing, prune, doctor warns still pass without relaxing product assertions
- [x] Unit tests cover inventory soft-fail and pack missing (including dangling symlink not missing)
- [x] No touched `.rs` file exceeds 1250 LOC; prefer ≤1000
- [x] `cargo test` green; `cargo clippy --workspace --all-targets -- -D warnings` clean

**Out of scope:**

- CLI Present/Ctx extraction ([[issues-150-cli-present-ctx-spine]])
- Membership module split ([[issues-151-membership-module-split]])
- Shared generate/pack filesystem copy ([[issues-152-fsutil-copy-tree]])
- Typed path resolve errors ([[issues-153-typed-path-resolve-errors]])
- Changing orphan definition, dirty semantics, or doctor fix allowlist
- Surfacing soft-fail as explicit warning objects in JSON
- Human formatter moves out of core

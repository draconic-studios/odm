# Config schema spine

## Question

What is the v1 `odm.config.yaml` schema for the design docs — maps vs lists, layout templates, `projects`, `progens` (paths anywhere), named progen combinations, actions, and what is explicitly deferred — written to `docs/reference/config.md`?

## Blocked by

- [[issues-2-domain-glossary]]
- [[issues-3-research-progenitor-surface]]

## Answer

Documented in `docs/reference/config.md`.

- Workspace config YAML; maps keyed by name; snake_case. *(Path later amended to `.odm/odm.config.yaml` by [[issues-7-multi-git-and-pins]].)*
- Keys: optional `name`, `projects`, `progens`, `progen_groups`, `actions`, `generators`.
- Project/Progen: `path` + optional `url` (+ optional Project `type`); no submodules; no layout templates.
- `actions` / `generators`: maps of bundle name → file path; bundle files hold definitions; merge by entity name; duplicates error.
- Action task spine: `run` + optional `dir`. Generator entry: `template` and/or `url`.
- Pin file `odm.lock.yaml` discovered by basename, not declared in config.
- Deferred: layout macros, worktree/agent-pack/env in config, JSON twin, rich executors, full template.toml.

# Typed path resolve errors

## Description

Path policy rejects absolute paths and `..` escapes via `resolve_under_root`, but several callers map failures to usage/workspace errors by inspecting message text (`contains("relative")` vs escape wording). Message edits can silently change exit codes. Make the contract typed.

## Affected

- odm-core path policy / config bundle validation / membership path checks
- odm-actions cwd resolve (same policy family)
- Tests that assert usage vs workspace exit codes on escape

## Impact

Brittle contracts; Primitive Obsession on English strings; risk of exit-code drift.

## Proposed Fix

See Agent Brief.

## Blocked by

None

## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement  
**Summary:** `resolve_under_root` (and siblings) fail with a typed absolute-vs-escape distinction; callers match the type instead of parsing error strings.

**Current behavior:**

- Path resolution under workspace root returns a stringly workspace error.
- Membership add, config bundle/task dir validation, and actions cwd resolution remap some failures to usage errors by checking whether the message contains particular English fragments.
- Exit codes for bad user paths vs internal workspace failures are part of the locked CLI matrix and must stay correct.

**Desired behavior:**

- Resolution exposes a structured failure (enum or error variant detail): at least **absolute** vs **escape** (and optionally other real variants if already distinguished). Unknown/OS IO errors remain distinct from policy rejects.
- All current `contains("relative")` / escape-string remaps become exhaustive matches on that type.
- User-facing messages may be reworded slightly if tests only lock codes/shapes — prefer keeping message clarity; do not break JSON `error.code` or exit codes for the same inputs.
- Config load vs membership add exit-code split (workspace vs usage) remains intentional where already documented — express it by matching the typed error at the boundary, not by string sniffing.

**Key interfaces:**

- `resolve_under_root` (or the canonical path-policy function family)
- `OdmError` usage/workspace mapping used by CLI exit spine
- Actions cwd resolution errors that today mention flag-oriented usage text — domain wording preferred at library edge; flag names may stay at CLI map if needed

**Acceptance criteria:**

- [x] No production caller maps path-policy failures via `message.contains(...)` for absolute vs escape
- [x] Existing CLI/unit tests for path escape on membership, bundles, action dirs, and run cwd still pass with the same exit codes
- [x] Typed failure is unit-tested directly (absolute input, `..` escape, happy relative)
- [x] `cargo test` green; `cargo clippy --workspace --all-targets -- -D warnings` clean
- [x] Touched files within LOC limits (≤1000 preferred, ≤1250 hard)

**Out of scope:**

- New path features (symlinks as roots, allowlists outside workspace)
- Inventory / CLI spine / fsutil / membership file split (except calling the new type)
- Changing which operations are usage vs workspace beyond replacing the remap mechanism

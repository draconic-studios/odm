# CLI Present/Ctx spine and thin dispatcher

## Description

issues-38 half-landed: `odm::commands` holds many DTOs/formatters, but main remains a god dispatcher (~discover/load/Git/print/exit per arm, dozens of `if out.json` branches, leftover success `json!`). Human list paths sometimes bypass DTOs and re-join. Thin aliases pretend to be command entrypoints. Finish the thin-bin architecture without renaming locked JSON fields.

## Affected

- odm binary main, output helper, cli flags (`--wt` resolution home)
- odm `commands` modules (become handlers + DTO + human, not DTO-only)
- CLI integration tests (contract gate)

## Impact

Every new verb multiplies dual-mode ritual; main is complexity-dense toward the 1k LOC target; contracts invent shapes in two homes.

## Proposed Fix

See Agent Brief.

## Blocked by

- [[issues-149-workspace-inventory-sample]] — preferred so project info sampling is already core-side before CLI spine moves handlers (soft block: may start in parallel if inventory lands first on core-only; do not reintroduce sampling glue in bin)

## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement  
**Summary:** Make the binary a thin adapter: open one context, dispatch by command family, present via one finish path; handlers return presentable values; delete dual print ritual and success-only `json!` in main.

**Current behavior:**

- Main matches on clap commands, repeatedly discovers root, loads workspace, constructs git, calls domain APIs, then branches on `--json` for print and exit.
- Some families have typed DTOs in `commands/*`; others still build success JSON with ad-hoc maps in main (sync, pin, init, many progen store arms).
- Human project/progen list can take a different data path than JSON (re-join vs DTO).
- Pure aliases exist (e.g. status snapshot = build_status).
- `--wt` truth is collected from argv in the dispatcher because clap global append is unreliable; clap field is help-oriented.
- Error envelope + clap parse failure JSON path already work — keep them.

**Desired behavior:**

- A single open-context step (skip for init as today) yields root, workspace, git, and resolved globals (`--project`, `--wt`, progen scope flags as needed).
- A presentation spine: success values that can serialize for `--json`, render human text, and optionally supply non-zero success exit (doctor not-ok, prune skipped nonempty, action run exit code). Main calls one finish helper instead of per-arm `if out.json`.
- Command families dispatch to library handlers that own orchestration + DTO + human (or return a type that embeds them). Main match arms become thin.
- Humans format DTOs (or the same presentable value) — no second join for list commands.
- Remaining success `json!` envelopes in main move to typed DTOs with stable field names.
- Delete pure identity wrappers that only rename a core call without policy.
- `--wt` collection/resolve lives next to the clap surface (or a flags helper), resolved once into context — one source of truth.
- Prefer shared named ok / materialize envelopes for project and progen add/rm JSON where shapes already match.
- Special cases allowed without forcing Present: child process passthrough (`project git`, run inherit stdio) may still return raw exit codes.

**Key interfaces:**

- Existing error envelope `{ ok: false, error: { code, message, detail? } }` and `exit_code` mapping — unchanged
- Locked success JSON shapes from integration tests — field names stable
- Clap command enums — parse stays separate from execute
- `run_context_prompt` share for context ≡ agent prompt — keep as pattern
- Materialize label map — keep single mapping

**Acceptance criteria:**

- [x] Main has no pervasive per-arm `if out.json { print_json } else { print human }` ritual for ordinary success paths (one finish/present helper)
- [x] Main contains no success-path `serde_json::json!` envelopes for commands that have (or gain) DTOs; pin/sync/init/progen store success payloads are typed
- [x] Project and progen list human output is derived from the same DTO (or presentable) as JSON — no dual observation/join
- [x] Pure alias command modules/functions that only forward to core without policy are removed or inlined
- [x] `--wt` resolved once into context; no second ad-hoc parse inside random arms
- [x] Existing CLI integration tests pass without relaxing JSON/exit assertions
- [x] `main.rs` complexity reduced (target well under 400 LOC preferred; must stay ≤1000)
- [x] No touched `.rs` file >1250 LOC
- [x] `cargo test` green; `cargo clippy --workspace --all-targets -- -D warnings` clean

**Out of scope:**

- Redesigning JSON field names or exit code meanings
- Moving status/doctor human formatters out of core in the same change (optional drive-by only if already touching)
- Inventory sampling implementation ([[issues-149-workspace-inventory-sample]] owns that)
- Membership production split ([[issues-151-membership-module-split]])
- Domain crate behavior changes unrelated to presentation
- MCP/TUI clients
